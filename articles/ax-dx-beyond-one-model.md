LLMとエージェントの登場で、AIを使うハードルはMLの時代よりずっと低くなりました。個人の生活でも仕事でも、その変化ははっきり感じるところです。

ところが、さまざまな現場や身の回りの人の話は少し違います。会社では「AIを入れたのに、現場は変わらない」と聞き、個人で使ってみたものの、何に使えばいいか分からずやめたという話もよく耳にします。同じ技術なのに、なぜこれほど違うのか。経験をもとに考えてみました。

## どこで止まるのか

会社でも個人でも、よく聞く話は似ています。

- 最新モデルを含め、高性能なエージェント向けLLMを使えない
- コストや社内ルールなどの制約で、使いたい環境で動かせない
- AIに詳しい人は現場を知らず、現場に詳しい人はAIの経験が少ない
- 整理して作ってみる時間がない

一つずつ解決すれば済む問題に見えます。でも、AX/DXを実感するには、これらがすべて一緒に、同時に動く必要があるのではないでしょうか。

## 自分で作って使っている「ブリーフィング」を例に

筆者は、「ブリーフィング」と一言送るだけで整理してくれるアシスタントを二つ使っています。一つは個人サーバー、もう一つは業務用サーバーで動いています。どちらも、これまで使ってきた履歴とためてきた知識をもとに、そのとき必要な情報を選んでくれるものです。

![二つのブリーフィング。個人サーバーはためてきた知識から週末に学ぶテーマを、業務用サーバーはある日の朝の予定と変更、確認することを整理する](/images/ax-dx-gates/ax-dx-gates-briefing-ja.png)

このブリーフィングが毎日動くまでには、いくつもの段階がありました。

| 段階 | 確認すること | 実際には |
|---|---|---|
| ① 開かれたモデル環境 | 最新・高性能なエージェント向けLLMを使えるか | 個人ではサービスを契約し、会社では社内ルールの範囲で確認して使う |
| ② ドメイン×技術 | 自分の仕事を知り、AIで何ができるかも知っているか | 自分の生活と仕事なので、何が大事か分かる。AIも扱ってきた |
| ③ コスト・セキュリティ | データの性質に合う実行環境があるか | 個人・一般・社内のデータを、それぞれ合う環境で動かす |
| ④ モデルの選び方 | 仕事に合うモデルを選べるか | 生成AI、MCP、スキル、機械学習モデルから、仕事に合うものを使う |
| ⑤ 時間・工数 | じっくり企画して作る工数があるか | 企画はドメイン知識をもとに自分で、具体化と開発は生成AIで、最終確認は人が |
| ⑥ 実際の運用 | 運用しながらフィードバックで改善し続けるサイクルがあるか | ほかのSaaSを使わずに数か月。機能を足しやすく、知識もたまっていく |

どれか一つでも欠けていたら、「一度試してみた」で終わっていたと思います。モデルが良くても何が大事か分からなければ必要のないことを整理してしまい、データを合う環境で動かせなければ、始めることすら難しいはずです。

ブリーフィングのほかにも、同じやり方で作って使っているものがあります。

| 区分 | 作って使っているもの |
|---|---|
| 個人 | このブログの執筆、個人のスケジュール管理、趣味の開発など |
| 仕事 | 自分の好みに合わせた要約・整理・分析と資料作成 |
| 仕事 | オンボーディング用ページ（フィードバックの反映と更新は自動、確認は人が） |
| 仕事 | 案件管理と簡単なデモ作成の自動化（セキュリティレベルに合うモデルを使用） |

どれも完成品ではありませんが、**考えたことの半分以上は実際に使われています。**

## ハードルを越えるたびに、実現の確率は理想より下がる

**環境が整っていても、ハードル（段階）を一つ越えるたびに、実現の確率は理想より少しずつ下がっていきます。** 技術の限界と現実の制約があるからです。どこかにボトルネックがあれば、もっと急に下がります。

冒頭のグラフは、これを経験から来る感覚で設定して描いたものです。環境がよく整った個人や企業なら、半分以上は実現できると考えました。

| 環境 | 設定 | 最後まで通ったあと |
|---|---|---|
| AX/DXに近づいている個人・企業 | 最適な環境があっても、技術の限界や人による確認作業で、段階ごとに約10%は減る | 半分以上 |
| ボトルネックのある環境 | コストや社内ルールなどの制約がボトルネックになり、使ってみる機会やリテラシーまで減って、段階ごとに30%以上減る | 約10% |

一つの段階では小さな差も、積み重なると大きく開きます。よく整った側でも半分近くは実現しません。技術の限界は確かにありますし、必ず人が確認すべきところもあるからです。

ボトルネックのある側は事情が違います。制約が多いとAIを実際に使ってみる機会が少なく、そのぶんリテラシーもたまりません。その結果、次のハードルでもまた止まってしまうのです。

## モデルと技術・サービスだけで変わるのか：人と文化も一緒に変わる必要がある

予算をかけて良いモデルを入れても、使う人が働き方を変えなければ何も変わりません。働き方を変えようとしても、試す時間と環境がなければ、また止まってしまいます。技術、ドメイン知識、AIを扱う力、実行環境、コストは、別々には解決しませんでした。

**最終的には、文化と人の意思決定が一緒に変わってこそ、AIを現実でしっかり使えるようになると考えています。**

これは会社に限らず、個人も同じです。次の質問に答えてみると、どこで止まっているのか、一つの段階だけが先に進んでいないかが見えてきます。

| 段階 | 自分に聞いてみること |
|---|---|
| ① | 最新・高性能なエージェント向けLLMを使えるか |
| ② | 仕事を知る人とAIを知る人が、同じ場にいるか（個人なら、両方を自分が知っているか） |
| ③ | データの性質に合う実行環境があるか |
| ④ | 仕事ごとに合うモデルを選んでいるか |
| ⑤ | じっくり企画して作る工数を、別に確保できているか |
| ⑥ | 実際に使いながら、フィードバックで直し続けるサイクルがあるか |

## 自分が気をつけていること

個人的に、AIを活用するときに重視しているのは、技術のレベルだけではありません。

いちばん大きいのは、ドメインとAI技術を結びつける力です。よく知っているドメインと仕事の流れに、どのAI技術が合うかが分かっていたので、始める前にできるかどうかを判断できました。判断するときは、主に次の点を見ます。

- 入力（いま）と出力（目標・理想）、その差を言葉にできるか
- その差を細かく分けて、それぞれに合う技術を当てはめられるか
- 間違えても大丈夫な仕事か、最後に人が確認できるか
- データを外に出してもよいか

いくつものモデルを合う環境で使えるインフラも、大きな助けになりました。ローカルとクラウド、自社モデルとフロンティアモデル、LLMとDocument AIまで選択肢が多く、データやセキュリティの条件で一つが使えなくても、別のものを使えました。そのおかげで、開発のハードルはかなり下がっています。

## AIの天井は上がり続ける

いま100とおいたAIの天井は、決まった値ではありません。モデルが良くなるたびに、150、200と上がっていきます。最近はそのペースもずっと速くなり、**ほぼ毎日のように新しいモデルが出ています。**

![天井が100、150、200と上がったときに、二つの環境に残る値とその差](/images/ax-dx-gates/ax-dx-gates-ceiling-ja.png)

最新モデルを使い続けてきた側は、新しいモデルが出ても慣れて活用するまでが早いです。そうでない側は試す機会が少なく、AIのリテラシーがだんだん足りなくなっていきます。実際の差は、グラフより速く開くかもしれません。

## 人・文化・インフラ・業務を一緒に

これらの段階のうち、技術だけで解決できるものは多くありません。個人の考え方と組織の文化が変わり、関係者とよく話しながら一緒に動くことが必要です。AIを試せるインフラと投資も、その結果を受け入れられる働き方も欠かせません。**人・文化・インフラ・業務が一緒に動いたとき**に、はじめてAX/DXを実感できるのだと思います。

一人の経験から出た考えですが、止まっている段階を解決しながらほかの段階も一緒に動かしていけば、すぐにとはいかなくても、AIの活用を実感できるところまでは進めるのではないかと思います。
