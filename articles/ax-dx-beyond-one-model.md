LLMとエージェントが登場して、AIを使うハードルはMLの時代よりずっと低くなりました。筆者も、個人の生活と仕事の両方で変化をはっきり感じています。

ところが、お客様や現場、身の回りの人と話してみると、事情は少し違うようです。会社では「AIを入れたのに、現場は変わらない」という話を聞きますし、個人で使ってみたものの、何に使えばいいか分からずやめてしまったという話もよく聞きます。同じ技術なのに、なぜこれほど違うのか。筆者の経験をもとに、考えたことを書いてみます。

## どこで止まるのか

会社でも個人でも、よく聞く話はだいたい次のようなものです。

- 最新モデルを含め、高性能なエージェント向けLLMを使えない
- コストや社内ルールなどの制約で、使いたい環境で動かせない
- AIに詳しい人は現場を知らず、現場に詳しい人はAIを使った経験が少ない
- 整理して作ってみる時間がない

一つずつ見ると、それぞれ別々に解決できそうな問題です。でも実際には、AIを使えるようになるまでに順に通る、いくつもの段階とつながっています。

## 筆者の経験：「ブリーフィング」を例に

たとえば筆者は、「ブリーフィング」と一言送るだけで整理された内容が返ってくるアシスタントを二つ使っていて、一つは個人サーバーに、もう一つは業務用サーバーにあります。どちらも、筆者がこれまで使ってきた履歴とためてきた知識をもとに、そのときに必要な情報を選んで整理してくれる仕組みです。

![二つのブリーフィング。個人サーバーはためてきた知識から週末に学ぶテーマを、業務用サーバーはある日の朝の予定と変更、確認することを整理する](/images/ax-dx-gates/ax-dx-gates-briefing-ja.png)

一言で済むように見えても、このブリーフィングが毎日動くまでには、いくつもの段階がありました。筆者の場合を段階ごとに書くと、次のとおりです。

| 段階 | 確認すること | 筆者の場合 |
|---|---|---|
| ① 開かれたモデル環境 | 最新・高性能なエージェント向けLLMを使えるか | 個人ではサービスを契約して使い、会社では社内ルールの範囲で確認して使う |
| ② ドメイン×技術 | 自分の仕事を知り、AIで何ができるかも知っているか | 自分の生活と仕事なので、何が大事かが分かる。AIも扱ってきた |
| ③ コスト・セキュリティ | データの性質に合う実行環境があるか | 個人・一般・社内のデータを、それぞれ合う環境で動かす |
| ④ モデルの選び方 | 仕事に合うモデルを選べるか | ローカルとクラウド、自社モデルとフロンティアモデルから選んで使う |
| ⑤ 時間・工数 | じっくり企画して作る工数があるか | 開発は生成AIで。まず個人サーバーで使ってみて、仕事にも広げた |
| ⑥ 実際の運用 | 運用しながら、フィードバックで改善し続けるサイクルがあるか | ほかのSaaSを使わずに数か月。機能の追加もしやすく、知識がたまっている |

どれか一つでも欠けていたら、ブリーフィングは「一度試してみた」で終わっていたと思います。モデルが良くても、何が大事かが分からなければ必要のないことを整理してしまいますし、分かっていても、個人・一般・社内のデータをそれぞれ合う環境で動かせなければ、始めること自体が難しくなります。

同じやり方で、このブログや趣味の開発、提案用のデモも作ってきました。どれも完成品ではありませんが、**考えたことの半分以上は、実際の生活と仕事で使われています。**

## 段階ごとに少しずつ減っていく

AIの活用は良いモデルひとつでは決まらず、これらの段階をすべて通って、はじめて形になります。そして、**環境が整っていても、段階ごとに技術の限界と現実の制約で、完全に実現できる可能性は少しずつ減っていきます。** 環境のどこかにボトルネックがあれば、その減り方はもっと急です。

冒頭のグラフは、これを筆者の感覚で設定して描いたものです。環境がいろいろ整っている個人や企業なら、半分以上は実現できると考えました。

| 環境 | 設定 | 最後まで通ったあと |
|---|---|---|
| AX/DXに近づいている個人・企業 | 各段階のハードルを越えても、約10%は実現しない | 半分以上 |
| ボトルネックのある環境 | コストや社内ルールなどの制約がボトルネックになり、30%以上は実現しない | 約10% |

一つの段階だけを見れば大きくない差が、段階を重ねるうちに大きく開きます。環境がよく整っている側でも、半分近くは実現しません。そこには技術の限界もありますが、人が最後に確認するよう、あえて残している部分もあります。

## 一つ解決しても次の段階で止まる：人と文化も一緒に変わる必要がある

では、止まっている段階を一つ解決すればよいのでしょうか。筆者はそうは考えていません。

予算を確保して良いモデルを入れても、使う人が働き方を変えなければ、何も変わりません。働き方を変えようとしても、試す時間やデータを動かす環境がなければ、また止まります。技術、ドメイン知識、AIを扱う力、実行環境、コストは、別々に解決できる問題ではありませんでした。

**最終的には、文化と人の意思決定全体が一緒に変わってこそ、AIを現実でしっかり使えるようになると考えています。**

これらの段階は、会社に限らず個人にもそのまま当てはまるものです。次の質問に答えてみると、自分や自分の組織がどこで止まっているのか、一つの段階だけが先に進んでいないかが見えてきます。

| 段階 | 自分に聞いてみること |
|---|---|
| ① | 最新・高性能なエージェント向けLLMを使えるか |
| ② | 仕事を知る人とAIを知る人が、同じ場にいるか（個人なら、両方を自分が知っているか） |
| ③ | データの性質に合う実行環境があるか |
| ④ | 仕事ごとに合うモデルを選んでいるか |
| ⑤ | じっくり企画して作る工数を、別に確保できているか |
| ⑥ | 実際に使いながら、フィードバックで直し続けるサイクルがあるか |

## 筆者の環境で減りにくかった理由

筆者の場合、段階ごとの減り方が小さかった理由は、技術そのものより別のところにありました。

いちばん大きかったのは、ドメインとAI技術を結びつける力です。筆者にしか分からないドメイン知識と仕事の流れがあり、そこにどのAI技術が合うかが分かりました。そのため、始める前に、この作業ができるかどうかを判断できました。判断するときは、主に次のことを確認します。

- 入力が決まった形式か
- 結果が正しいか確認できるか
- 間違えても大丈夫な仕事か、最後に人が確認できるか
- データを外に出してもよいか

いくつものモデルを、合う環境で使えるインフラも大きな助けになりました。ローカルとクラウド、自社モデルとフロンティアモデル、LLMとDocument AIまで選択肢が多く、データの性質やセキュリティの条件で一つが使えなくても、別のものを使えました。そのおかげで、開発のハードルはかなり下がっています。

## AIの天井は上がり続ける

もう一つあります。いま100とおいたAIの天井は、決まった値ではありません。モデルが良くなるたびに、150、200と上がっていきます。しかも最近は、そのサイクルがずっと速くなり、**ほぼ毎日のように新しいモデルが発表されています。**

![天井が100、150、200と上がったときに、二つの環境に残る値とその差](/images/ax-dx-gates/ax-dx-gates-ceiling-ja.png)

残る比率が同じでも、差は天井と一緒に開いていく計算です。最新モデルを使い続けてきた個人や組織は、新しいモデルが出ても、慣れて活用するまでが早いです。そうでない個人や組織は、新しいモデルを試す機会が少ないため、AIを活用するリテラシーがだんだん足りなくなっていきます。実際の差は、グラフよりも速く開くかもしれません。

## 人・文化・インフラ・業務を一緒に

これらの段階のうち、技術だけで解決できるものは多くないように思います。個人の考え方と組織の文化が変わり、関係者とよく話しながら一緒に動くことが必要です。AIを試せるインフラと投資も、その結果を受け入れられる働き方も欠かせません。**人・文化・インフラ・業務が一緒に動いたとき**に、はじめてAX/DXを実感できるのだと思います。

この記事は、筆者一人の経験から出た考えです。それでも、止まっている段階を解決しながら、ほかの段階も一緒に動かしていけば、すぐにとはいかなくても、AIの活用を実感できるところまでは進めるのではないかと思います。
